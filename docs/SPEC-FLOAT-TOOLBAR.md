> **קהל יעד:** דאן + סאמר + מרקוס.
> **חוקה רלוונטית:** CLAUDE.md §8 (סרגל צף) — `#ctxBar` הוא `position:fixed`, נסגר בלחיצה-חוץ+Escape, `#ctxMore` נפתח **כלפי מטה** (לא מתהפך מעלה), פלטות מקבלות z-index מעל הסרגל.

## 7. "אפשרויות נוספות" — נגישות, ולא להיתקע בתחתית הדף

**מצב נוכחי בקוד:**
`moreBtn([...])` מוסיף כפתור "עוד" שפותח `#ctxMore` (CSS ~1057). לפי CLAUDE.md §8 התפריט נפתח **כלפי מטה**, ואם אין מקום — גובה מוגבל עם גלילה (לא מתהפך מעלה). `positionRect()` (~8877) מצמיד את הסרגל מתחת לבחירה, ואם אין מקום — מצמיד לתחתית המסך (`pinned=ih-bh-8`).

**מה לא נוח (דיווח המשתמש):**
כשפותחים "אפשרויות נוספות" והסרגל קרוב לתחתית, התפריט `#ctxMore` "נתקע בתחתית הדף" — חלקו עלול להיחתך מתחת לקצה התחתון של חלון התצוגה, או לדרוש גלילה לא נוחה.

**מצב רצוי:**
- `#ctxMore` ייפתח כלפי מטה אך **תמיד גלוי במלואו בתוך ה-viewport**:
  - לחשב `spaceBelow = window.innerHeight - anchorRect.bottom - 8`.
  - `maxHeight = min(תוכן, spaceBelow)`; אם `spaceBelow` קטן מסף (למשל 160px) — להצמיד את **הסרגל כולו** מעט מעלה כך שיישאר מקום לתפריט (לא להפוך את כיוון הפתיחה — לשמור §8).
  - `#ctxMore { overflow-y:auto }` כבר קיים; לוודא ש-`max-height` מחושב דינמית בעת הפתיחה ולא קבוע.
- ה-`#ctxMore` תמיד עם `position:fixed` ו-z-index מעל `#ctxBar` (קיים).

**input → output:**
```
סרגל קרוב לתחתית המסך → לחיצה על "עוד"
→ #ctxMore נפתח כלפי מטה עם max-height=spaceBelow, גלילה פנימית אם צריך
→ אף פריט לא נחתך מתחת לקצה התצוגה
```

**מידות/CSS:**
```css
#ctxMore { /* קיים: padding/border-radius/min-width */ overflow-y:auto; }
/* max-height נקבע ב-JS בעת הפתיחה: el.style.maxHeight = spaceBelow+'px'; */
```

**איך Word:** תפריטי-המשנה של Word נצמדים תמיד בתוך המסך הגלוי; כשאין מקום הם מקבלים גלילה פנימית או דוחפים מעט את העוגן. אף פעם לא נחתכים.

**שלבי מימוש:**
1. בפונקציה שפותחת את `#ctxMore` (`moreBtn`/הקוד שמציג אותו): לחשב `spaceBelow` ולהגדיר `ctxMore.style.maxHeight`.
2. ב-`positionRect` כשהסרגל מוצמד-לתחתית (`pinned`), לוודא שנשאר מרווח מינימלי לתפריט.

**בדיקה למרקוס:** בחר טקסט קרוב לתחתית → "עוד" → התפריט גלוי במלואו (אין `scrollHeight>clientHeight` שנחתך מחוץ ל-viewport).

## 8. שינוי גודל גופן בסרגל הצף — ✅ קיים, לוודא

**מצב נוכחי בקוד:**
**כבר מומש.** `buildText()` מוסיף `_sizeChip` (`.ctx-size-chip`, ~9023) שמציג את הגודל הנוכחי (`readCurrentFontSizePt()`) ופותח `#ctxSizePop` (CSS ~1715) — שדה הזנה + רשת גדלים. בנוסף כפתורי `fontDown`/`fontUp` (~9026–9027) עם `_freezePos` כדי שהסרגל לא יקפוץ בלחיצות חוזרות.

**מה לוודא:** שה-chip מתעדכן (`updateSizeChip()`) אחרי כל שינוי, ושהפופ-אפ נשאר על המסך (`#ctxSizePop position:fixed; z-index:10051` — קיים).

**input → output:**
```
סמן טקסט → הסרגל מציג "14 ▾"
לחץ על ה-chip → #ctxSizePop נפתח עם רשת [8..72] + שדה מותאם
בחר 24 → טקסט 24pt, chip→"24", הסרגל לא קופץ
לחץ A▲ → 26, A▼ → 22 (אפשר ברצף)
```

**מצב רצוי:** אין שינוי מהותי. ליטוש בלבד: לוודא ש-`#ctxSizePop` נסגר ב-Escape ובלחיצה-חוץ (`closeSizePop`).

**איך Word:** ה-Mini-Toolbar של Word כולל font-size dropdown + Grow/Shrink. תואם.

## 9. שינוי סגנון/גופן בסרגל הצף — ✅ קיים, לוודא

**מצב נוכחי בקוד:**
**כבר מומש.** `buildText()` מוסיף `makeFontFamilySelect()` (~9021) — `<select class="ctx-font">` בורר משפחת-גופן ישירות בסרגל (CSS ~1692, RTL, חץ מותאם). שומר בחירה ב-mousedown ומשחזר לפני `execCommand` (כמו `#fontNameSelect`).

**מה לא נוח / מה חסר (דיווח המשתמש):**
המשתמש ביקש גם **סגנון פסקה** (כותרת/גוף-טקסט) בסרגל הצף, לא רק משפחת-גופן.

**מצב רצוי:**
- להוסיף ל-`buildText()` בורר-סגנון קומפקטי (לפני בורר הגופן או אחריו), מקביל ל-`#blockStyleBtn` של סרגל הבית: כפתור קטן שמציג את הסגנון הנוכחי ("גוף טקסט ▾") ופותח רשימה קצרה: גוף טקסט / כותרת 1 / כותרת 2 / כותרת 3 / ציטוט.
- בחירה → `execCommand('formatBlock', tag)` (אותו מנגנון כמו §4 בסרגל הבית) → `scheduleSave` + `requestAnimationFrame(updatePagination)`.
- מטעמי רוחב בסרגל הצף: למקם את בורר-הסגנון בתוך תפריט "עוד" אם הסרגל צפוף, או כ-chip קומפקטי `.ctx-style-chip` ברוחב ~84px.

**input → output:**
```
סמן פסקה → הסרגל מציג "גוף טקסט ▾" (בנוסף לבורר הגופן הקיים)
בחר "כותרת 1" → הפסקה הופכת ל-H1, ה-chip מציג "כותרת 1"
```

**מידות/CSS (בסוף ה-`<style>`):**
```css
#ctxBar .ctx-style-chip { height:38px; max-width:96px; gap:3px; font-size:12.5px;
  font-weight:600; padding:8px 9px; }
#ctxBar .ctx-style-chip .caret { font-size:9px; opacity:.8; }
```
(לעצב את הפופ-אפ באותו סגנון כהה של `#ctxSizePop`.)

**איך Word:** ה-Mini-Toolbar של Word כולל Styles dropdown לצד font/size. תואם.

**שלבי מימוש:**
1. ב-`buildText()` (~9021, ליד `makeFontFamilySelect()`): להוסיף `_styleChip` שפותח פופ-אפ בחירת-סגנון.
2. עדכון ה-chip מתוך `_syncBlockStyle()` (כמו §4 בסרגל הבית — אותה מקור-אמת).
3. CSS בסוף.

**בדיקה למרקוס:** בחירת טקסט מציגה גם בורר-סגנון; שינוי ל-H1 מעדכן את הפסקה ואת ה-chip.

## 10. זמן היעלמות — הסרגל נשאר זמן רב מדי

**מצב נוכחי בקוד:**
הסרגל **מבוסס-בחירה**, לא מבוסס-hover: הוא מוצג כל עוד יש בחירת טקסט/אובייקט נבחר, ונסגר ב-`hideBar()` (~8690) דרך לחיצה-חוץ/Escape (§8). `scheduleRefresh()` (~9582) הוא `setTimeout(refreshCtx, 0)` — מיידי. אין כרגע מנגנון של "היעלמות אחרי שהעכבר עזב".

**מה לא נוח (דיווח המשתמש):**
"הסרגל הצף לא נעלם מהר כשהעכבר לא עליו — לקצר זמן היעלמות." המשתמש מצפה שהסרגל ייעלם **מהר** כשהבחירה מתבטלת או כשהמשתמש מסיט את העכבר/הסמן הרחק ממנו, ולא יישאר "תלוי" כשהבחירה כבר התרוקנה.

**מצב רצוי:**
- כש**הבחירה מתרוקנת** (collapsed range / `selection.isCollapsed`) ולא לוחצים על הסרגל — להסתיר את הסרגל **תוך ~120ms** (לא מיידית, כדי לאפשר מעבר מהבחירה אל כפתור בסרגל, אך מהר).
- מנגנון: `refreshCtx()` כבר נקרא ב-`selectionchange`; אם הבחירה collapsed ו-`document.activeElement` אינו הסרגל — לקבוע `_hideTimer = setTimeout(hideBar, 120)`.
- **לבטל את הטיימר** אם העכבר נכנס ל-`#ctxBar` (`mouseenter`) או אם נוצרת בחירה חדשה — כדי לא להסתיר תוך כדי שימוש.
- שמירה על §8: עדיין נסגר ב-Escape ובלחיצה-חוץ; זה רק מקצר את ההיעלמות בעת איבוד-בחירה.

**input → output:**
```
סמן טקסט → סרגל מופיע
לחץ במקום ריק (בחירה מתרוקנת) → סרגל נעלם תוך ~120ms (מהר)
סמן טקסט → הזז עכבר אל כפתור בסרגל → הסרגל נשאר (הטיימר בוטל ב-mouseenter)
Escape → נסגר מיד (קיים)
```

**מידות/CSS:** ללא. (אופציונלי: `transition: opacity .1s` ל-fade-out עדין — אבל לא transform, לפי הלקח של סאמר על `@keyframes ctxPop` fade-only.)

**איך Word:** ה-Mini-Toolbar של Word נעלם מהר מאוד כשהעכבר מתרחק ממנו / הבחירה אובדת (~100ms). זה היעד.

**שלבי מימוש:**
1. במאזין `selectionchange`/`refreshCtx`: אם `_ctxType==='text'` והבחירה collapsed → `clearTimeout(_hideTimer); _hideTimer=setTimeout(hideBar,120)`.
2. אם יש בחירה → `clearTimeout(_hideTimer)`.
3. `bar.addEventListener('mouseenter', ()=>clearTimeout(_hideTimer))`.
4. לא לגעת ב-`hideBar()` עצמו ולא בהיגיון האובייקטים (אובייקט נבחר נשאר עד ביטול-בחירה).

**בדיקה למרקוס:** בחירת טקסט→ביטול בחירה → הסרגל נעלם תוך ~120ms; העברת עכבר אל הסרגל מבטלת היעלמות.

## 11. "אפשרויות נוספות" — להסיר Undo/Redo, להאריך, ולהקטין כפתורים ~15%

**מצב נוכחי בקוד:**
`#ctxMore` (CSS ~1057, ~1274) — כפתורים `font-size:13.5px; padding:10px 12px; border-radius:10px` (במובייל), `min-width:196px`. תוכן "עוד" ל-`buildText()` (~9037): כתב-עילי, כתב-תחתי, יישור דו-צדדי, מפריד, נקה-עיצוב.

**בדיקה:** Undo/Redo **אינם** כיום ב-`#ctxMore` של הטקסט (טוב). יש לוודא שאין Undo/Redo בשום וריאנט של "עוד" (טקסט/תיבה/אובייקט). אם קיימים — להסיר (לא שייכים לסרגל-בחירה הקשרי; מקומם בסרגל הבית).

**מה לא נוח (דיווח המשתמש):**
1. אם יש Undo/Redo ב"עוד" → להסיר.
2. הסרגל/התפריט "קצר מדי" → להאריך (להגדיל `min-width`).
3. הכפתורים גדולים → להקטין ~15%.

**מצב רצוי — מידות מדויקות:**
- **הסרה:** לוודא שאין פריטי `undo`/`redo` ברשימות `moreBtn(...)` של buildText/buildTextbox/buildImage.
- **הארכה:** `#ctxMore { min-width: 226px; }` (מ-196 → +~15% רוחב לתפריט; מאריך את הסרגל-המורחב).
- **הקטנת כפתורים ~15%:**
  | מאפיין | נוכחי (מובייל) | רצוי (−15%) |
  |---|---|---|
  | `#ctxMore button font-size` | 13.5px | **11.5px** |
  | `#ctxMore button padding` | 10px 12px | **8.5px 10px** |
  | `#ctxMore button .ico font-size` | 16px | **13.5px** |
  | `#ctxMore button border-radius` | 10px | **8.5px** |
  - בדסקטופ (CSS ~1065): `font-size` נוכחי לבדוק → להקטין באותו יחס (~14px→12px, padding בהתאם).

**input → output:**
```
לחיצה על "עוד" → תפריט ברוחב 226px, כפתורים קומפקטיים ב-~15% פחות
אין בתפריט "בטל"/"חזור"
```

**מידות/CSS (בסוף ה-`<style>`, גובר על הקיים):**
```css
#ctxMore { min-width: 226px; }
#ctxMore button { font-size: 11.5px; padding: 8.5px 10px; border-radius: 8.5px; }
#ctxMore button .ico { font-size: 13.5px; width: 18px; }
```

**איך Word:** ה-overflow של ה-Mini-Toolbar ב-Word קומפקטי ומכיל רק פעולות-עיצוב הקשריות — לא Undo/Redo (אלה ב-QAT/Ribbon). תואם הבקשה.

**שלבי מימוש:**
1. סריקת קוד: לוודא אין `undo`/`redo` ב-`moreBtn`. אם יש — להסיר את הפריטים.
2. CSS בסוף ה-`<style>` עם הערכים לעיל (גובר על ~1057/~1274 בזכות סדר-מאוחר).

**בדיקה למרקוס:** מדידת `getComputedStyle` של `#ctxMore button` → `font-size:11.5px`, `padding:8.5px 10px`; `min-width` של `#ctxMore` → 226px; אין כפתור undo/redo.

## 12–13. תיבת טקסט — סרגל צף רלוונטי, ללא כפילות עם סרגל הבית

**מצב נוכחי בקוד:**
`buildTextbox(obj)` (~9078): כפתורי **צבע רקע לתיבה** (`SIC.fill`), **הצג/הסתר מסגרת** (`SIC.frame`, toggle border 1.5px), מפריד, ואז `addCopyBtn / addLockBtn / addMultiBtn / addDeleteBtn`, `addOpacityCtrl` (שקיפות). תפריט "עוד" כולל **כפילות מיותרת**: B/I/U/מרקר/יישורים (~9092–9099) — אלה כפילות של פעולות עיצוב-טקסט שכבר נגישות כשעורכים בתוך התיבה דרך סרגל-הטקסט הרגיל.

**מה לא נוח (דיווח המשתמש):**
1. הסרגל הצף של תיבת-טקסט צריך כפתורים **רלוונטיים לתיבה**: שקיפות, מסגרת, מחיקה.
2. **ללא כפילות עם סרגל הבית** — להסיר את B/I/U/יישורים מ"עוד" של התיבה (אלה כבר זמינים בסרגל הבית/הסרגל-הצף-של-טקסט כשהסמן בתוך התיבה).

**מצב רצוי — סט הכפתורים הסופי לתיבת-טקסט:**
| כפתור | קיים? | פעולה |
|---|---|---|
| 🎨 צבע רקע תיבה | ✅ | `obj.style.background` |
| ▭ מסגרת (סגנון/עובי/צבע) | ✅ חלקי | toggle + להרחיב: בחירת עובי וצבע מסגרת |
| 🔅 שקיפות | ✅ | `addOpacityCtrl` (0–100%) |
| ⧉ שכפול | ✅ | `addCopyBtn` |
| 🔒 נעילה | ✅ | `addLockBtn` |
| 🗑 מחיקה | ✅ | `addDeleteBtn` |
| ⬆/⬇ ריבוד | ✅ ב"עוד" | `layerMoreItems` |

**שינויים נדרשים:**
1. **להסיר מ"עוד" של תיבת-טקסט** את הפריטים B/I/U/מרקר/יישור-ימין/מרכז/שמאל (~9092–9099) — כפילות. עיצוב-הטקסט נעשה כשעורכים בתוך `.tb-content` (הסרגל-הצף-של-טקסט הרגיל מטפל).
2. **לשדרג את "מסגרת"** מ-toggle בלבד למשהו עשיר יותר: לחיצה קצרה = toggle מהיר (קיים); הוספת אופציה ב"עוד" ל"עובי מסגרת" (1/1.5/3px) ו"צבע מסגרת" (פתיחת `openColors`).
3. תפריט "עוד" של התיבה יישאר רק עם: ריבוד (קדימה/אחורה), עובי-מסגרת, צבע-מסגרת.

**input → output:**
```
בחר תיבת-טקסט (לא בעריכה פנימית) → הסרגל: רקע · מסגרת · שקיפות · שכפול · נעילה · מחיקה · עוד(ריבוד/מסגרת)
"עוד" אינו מכיל B/I/U/יישור (כפילות הוסרה)
לחיצה כפולה בתוך התיבה → עריכת טקסט → הסרגל-הצף-של-טקסט הרגיל (B/I/U/גופן/גודל) מופיע
```

**מידות/CSS:** ללא חדש; משתמש בכפתורי `#ctxBar` הקיימים.
