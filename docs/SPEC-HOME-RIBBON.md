## 1. זום +/- בלחיצה — `#zoomIn` / `#zoomOut`

**מצב נוכחי בקוד:**
כבר קיימים `#zoomOut` (תווית `−`), `#zoomIn` (תווית `+`), `#zoomReset`, ומחוון `#zoomSlider` **בשורת הסטטוס התחתונה** (HTML ~2828). `applyZoom(pct)` (~9741) מגדיר `#pageStack.style.zoom` בטווח 50–200, צעד 10, + Ctrl+גלגלת (CLAUDE.md §10). הלשונית "תצוגה" מפנה אליהם דרך `vwZoomIn`/`vwZoomOut` (~11142).

**מה לא נוח (דיווח המשתמש):**
המשתמש "לא מצא" את כפתורי הזום — הם רק בשורת הסטטוס התחתונה, קטנים, בלי תצוגת אחוז בולטת. אין discoverability בסרגל הבית עצמו, ששם המשתמש מצפה למצוא פקדי תצוגה מהירים.

**מצב רצוי:**
להוסיף **קבוצת זום קומפקטית בקצה סרגל הבית** (אחרי קבוצת undo/redo), המשקפת את הפקדים הקיימים — לא מנגנון חדש, רק קיצור-דרך נגיש:
- `[ − ] [ 100% ] [ + ]` — שלושה אלמנטים.
- לחיצה על `−`/`+` קוראת בדיוק ל-`document.getElementById('zoomOut'/'zoomIn').click()` (כמו שעושה לשונית התצוגה כבר היום — אפס לוגיקה כפולה).
- התווית האמצעית `100%` היא כפתור שלחיצה עליו = `applyZoom(100)` (איפוס), והיא מתעדכנת אוטומטית מתוך `applyZoom` (להוסיף עדכון של אלמנט זה בסוף `applyZoom`).

**input → output:**
```
לחיצה על +  → זום 100→110, התווית בסרגל ובסטטוס מציגות "110%", #pageStack.style.zoom=1.1
לחיצה על 100% → זום חוזר ל-100%
Ctrl+גלגלת (קיים) → גם מעדכן את התווית בסרגל הבית
גבול: 50% (לא יורד מתחת), 200% (לא עולה מעל) — הקלמפ כבר ב-applyZoom
```

**מידות/CSS מומלצים (CSS בסוף ה-`<style>`):**
```css
.hr-zoom { display:inline-flex; align-items:center; gap:2px;
  border:1px solid var(--border); border-radius:9px; padding:2px; }
.hr-zoom button { min-width:30px; height:30px; border:none; background:transparent;
  border-radius:7px; cursor:pointer; font-size:14px; color:var(--text); }
.hr-zoom button:hover { background:rgba(99,102,241,.12); color:var(--primary); }
.hr-zoom .hr-zoom-val { min-width:46px; font-size:12px; font-variant-numeric:tabular-nums;
  font-weight:600; text-align:center; cursor:pointer; }
```
יעד מגע: 30px (מקובל בתוך ribbon; ≥44px לא מתאים לצפיפות הסרגל — מקובל בתעשייה לפקדי-משנה).

**איך Word:** Word מציג פקד זום `− [סליידר] +  100%` בפינה הימנית-תחתונה של שורת הסטטוס. MyWord כבר עושה זאת; התוספת בסרגל היא נוחות נוספת.

**שלבי מימוש:**
1. HTML: אחרי קבוצת undo (סגירת `</div>` של `.group` ב-~2620, לפני `</header>`) להוסיף `<div class="group"><div class="hr-zoom">…</div></div>` עם 3 אלמנטים.
2. JS לפני `buildColorPalette();`: לחווט 3 מאזיני click → `zoomOut/zoomReset/zoomIn`.
3. בסוף `applyZoom(pct)` (~9741): `const v=document.querySelector('.hr-zoom-val'); if(v) v.textContent=pct+'%';`
4. CSS בסוף ה-`<style>`.

**בדיקה למרקוס:** לחיצה על `+` בסרגל הבית מגדילה `#pageStack.style.zoom`; התווית מתעדכנת; ערכים נקלמפים 50–200.

## 2. כפתורי צבע — Split-button (גוף=צבע אחרון, חץ=פלטה)

**מצב נוכחי בקוד:**
**כבר מומש כ-split-button.** `#colorBtn` ו-`#bgColorBtn` הם `.color-btn.has-caret` (HTML ~2502, ~2519). יש להם `<span class="cbtn-caret">▾</span>` כאזור לחיצה נפרד (CSS ~1753), ו-`--cur-color` נשמר על הכפתור. בסרגל הצף `openColors(b,...)` נפתח מהחץ ▾ של `#colorBtn`/`#bgColorBtn` (CLAUDE.md §11, §16 שלב 2 — `openColorWheel`).

**מה לא נוח (דיווח המשתמש):**
המשתמש כתב "חסר חץ לבחירת צבע" — כלומר **ההתנהגות של גוף-הכפתור מול החץ לא מובחנת מספיק ויזואלית**, והגוף **לא מחיל את הצבע האחרון** אלא פותח פלטה (או להפך). הציפייה הברורה: גוף = החל-מיידית את הצבע המוצג; חץ = פתח בורר.

**מצב רצוי (חוזה ה-split-button המלא):**
- **לחיצה על גוף הכפתור** (החלק עם ה-`A`/המרקר + ה-swatch): מחילה **מיד** את הצבע השמור ב-`--cur-color` על הבחירה, **בלי לפתוח פלטה**.
  - אם אין בחירת טקסט → `showHint('סמן טקסט קודם')`.
- **לחיצה על החץ ▾** (`.cbtn-caret`): פותחת את הפלטה/`openColorWheel`. בחירת צבע שם → מחילה **וגם** מעדכנת `--cur-color` ל-swatch כך שהלחיצה-הגוף הבאה תחזור על אותו צבע.
- ויזואלית: קו הפרדה דק בין הגוף לחץ (כבר קיים `border-inline-end` ב-`.cbtn-caret`), ועל hover רק החלק שמעליו העכבר מודגש (גוף מול חץ).

**input → output:**
```
פעם ראשונה: גוף colorBtn לחוץ ללא צבע מוגדר → מחיל אדום ברירת-מחדל (#dc2626)
לחיצה על ▾ → openColorWheel → בחר כחול → טקסט כחול, swatch נצבע כחול, --cur-color=#2563eb
לחיצה חוזרת על גוף → מחיל כחול מיד (ללא פלטה)
bgColorBtn זהה: גוף=מרקר אחרון, ▾=בחירת צבע מרקר, ▾ כולל "✕ הסר רקע"
```

**מידות/CSS:** קיים ב-`.color-btn.has-caret { width:48px }` + `.cbtn-caret { width:15px }`. אין צורך לשנות מידות; רק לוודא שאזורי-הלחיצה מופרדים (event על `.cbtn-caret` עם `stopPropagation` כך שלא יעלה לגוף).

**איך Word:** Font Color / Highlight ב-Word הם split-button קלאסי: לחיצה על האות מחילה את הצבע הנראה, לחיצה על המשולש פותחת את הגלריה. זה בדיוק היעד.

**שלבי מימוש:**
1. לוודא ב-JS (חיווט `#colorBtn`/`#bgColorBtn`): מאזין click על **הגוף** מפריד בין `e.target.closest('.cbtn-caret')` (→ פתח בורר) לבין שאר הכפתור (→ `applyColor` עם `getComputedStyle(btn).getPropertyValue('--cur-color')`).
2. בקולבק של בחירת צבע: לעדכן `btn.style.setProperty('--cur-color', color)`.
3. `.cbtn-caret` מקבל `e.stopPropagation()` ב-click כדי שלא יפעיל את הגוף.
4. אותו דבר לשני הכפתורים. ה-CSS כבר במקום.

**בדיקה למרקוס:** סמן טקסט → לחץ גוף `#colorBtn` (לא החץ) → טקסט מקבל את `--cur-color`, פלטה **לא** נפתחה. לחץ ▾ → פלטה נפתחת.

## 3. קיבוץ וחידוד כפתורי "הזזת טקסט"

**מצב נוכחי בקוד:**
בקבוצת היישור/הזחה (HTML ~2561–2578): 4 כפתורי יישור (`.align-btn`), `#btnIndent`, `#btnOutdent`, `#btnLineSpacing`. כולם בקבוצה אחת ללא תווית-קבוצה (`<div class="group">` בלי `.label`). האייקונים: יישור = SVG ברור; הזחה = `⇥`/`⇤` (תווי גליף לא חד-משמעיים); מרווח = `↕`.

**מה לא נוח (דיווח המשתמש):**
"יותר מדי כפתורי הזזת טקסט לא ברורים" — הבעיה: ⇥/⇤ נראים דומים זה לזה ודומים ל-Tab; אין הפרדה ויזואלית בין "יישור" (אופקי) ל"הזחה" (כניסה) ל"מרווח" (אנכי); אין תווית-קבוצה.

**מצב רצוי:**
- **לפצל לשתי קבוצות ויזואליות** עם מפריד דק (`sep`) ביניהן בתוך אותו `.group`:
  - קבוצה א' "יישור": 4 כפתורי SVG (קיימים, טובים).
  - קבוצה ב' "הזחה ומרווח": `#btnIndent`, `#btnOutdent`, `#btnLineSpacing`.
- **להחליף אייקוני הזחה** ל-SVG ברורים (חץ + קווי טקסט), במקום `⇥`/`⇤`:
  - הזחה פנימה (RTL): קווי טקסט עם חץ דוחף מימין פנימה.
  - הזחה החוצה: חץ מושך החוצה.
- **tooltips מחודדים** עם דוגמה: למשל `"הגדל כניסה — דוחף את הפסקה פנימה מהשוליים (כמו Tab בתחילת פסקה)"`.
- להוסיף תווית-קבוצה אחת `"פסקה"` מתחת לכל הקבוצה (להפוך `<div class="group">` ל-`<div class="group-titled">` עם `<div class="label">פסקה</div>`), כדי שתואם את שאר הקבוצות בעלות-תווית.

**input → output:**
```
hover על "הגדל כניסה" → tooltip: "הגדל כניסה — דוחף את הפסקה פנימה מהשוליים"
לחיצה → _applyIndent(+40) (קיים) → margin-inline-start += 40px
אייקון SVG ברור מבדיל בין פנימה/החוצה לפי כיוון החץ
```

**מידות/CSS:** ללא שינוי מידות. SVG חדש בגודל `15×13` כמו ה-`.align-btn` הקיימים (אותו viewBox-style). מפריד: שימוש ב-`sep`/בורדר דק `border-inline-start:1px solid var(--border); padding-inline-start:4px; margin-inline-start:2px`.

**איך Word:** Word ב-Home > Paragraph מקבץ יישור, הזחה (Increase/Decrease Indent עם אייקוני חץ+קווים ברורים), ומרווח-שורות בקבוצה אחת מסומנת "Paragraph". האייקונים שם חד-משמעיים — חץ עם קווי-טקסט.

**שלבי מימוש:**
1. HTML ~2565–2566: להחליף את תוכן `#btnIndent`/`#btnOutdent` ב-SVG (לשמור על ה-id והמאזינים הקיימים — `_applyIndent` לא משתנה).
2. לעדכן `title` של שלושת הכפתורים לטקסט מחדד.
3. להוסיף `<div class="label">פסקה</div>` ולהפוך ל-`group-titled` (אופציונלי אך מומלץ לעקביות).
4. אין שינוי JS לוגי.

**בדיקה למרקוס:** הכפתורים שומרים על id ועל פעולת `_applyIndent`; tooltip מעודכן; אייקונים שונים זה מזה ויזואלית.

## 4. "גוף טקסט" — בורר סגנון פסקה פרקטי

**מצב נוכחי בקוד:**
ה-`<select id="blockStyle">` הישן מוסתר (`display:none`, ~2541) ונשאר רק לסנכרון `_syncBlockStyle()`. במקומו יש כבר **כפתור-תפריט** `#blockStyleBtn` (`.bs-btn`, ~2549) שפותח `#blockStyleMenu` (`.bs-menu`) עם 5 אפשרויות: גוף טקסט / כותרת 1–3 / ציטוט, כל אחת מעוצבת בגודלה (HTML ~2551–2555). הכפתור עצמו מציג רק `¶▾`.

**מה לא נוח (דיווח המשתמש):**
"גוף טקסט לא פרקטי" — הבעיות:
1. **כפתור הטריגר מציג רק `¶`** ולא את **שם הסגנון הנוכחי**, כך שאי-אפשר לדעת במבט מה הסגנון של הפסקה הנוכחית.
2. אין **תצוגה מקדימה** ברורה של הסגנון בתוך התפריט (יש גודל-גופן בלבד; אין דוגמת-טקסט עם הצבע/המרווח האמיתי).
3. רוחב התפריט 150px צר לעברית.

**מצב רצוי:**
- **כפתור הטריגר יציג את שם הסגנון הנוכחי**: "גוף טקסט ▾" / "כותרת 1 ▾" וכו', מתעדכן מ-`_syncBlockStyle()` (במקום `¶`).
- **כל פריט בתפריט יוצג כתצוגה מקדימה אמיתית** — שורת דוגמה "כותרת ראשית" בגודל/משקל/צבע של אותו סגנון (כבר חלקית), + תווית-משנה קטנה אפורה ("Heading 1") מתחת.
- **רוחב תפריט** → 200px.
- **סימון הסגנון הפעיל** (`.cur`) בתפריט.

**input → output:**
```
סמן בתוך <h1> → כפתור מציג "כותרת 1 ▾", הפריט "כותרת 1" מסומן בתפריט
בחר "ציטוט" → execCommand('formatBlock','blockquote') (קיים), הכפתור מציג "ציטוט ▾"
Enter → פסקה חדשה P → הכפתור חוזר ל-"גוף טקסט ▾"
```

**מידות/CSS:**
```css
.bs-menu { width:200px; }                 /* מ-150 */
.bs-btn { min-width:96px; justify-content:space-between; gap:6px;
  padding:6px 10px; font-weight:600; }     /* מציג טקסט, לא רק ¶ */
.bs-opt { display:flex; flex-direction:column; gap:1px; }
.bs-opt .bs-sub { font-size:10px; color:var(--text-soft); font-weight:400; }
.bs-opt.cur { background:#eef2ff; }
```

**איך Word:** ה-Style Gallery של Word מציג את שם הסגנון הנוכחי מודגש, וכל פריט בגלריה הוא תצוגה-מקדימה חיה של הסגנון. זה היעד.

**שלבי מימוש:**
1. HTML ~2549: `#blockStyleBtn` מתוכן `¶<span class="caret">▾</span>` → `<span class="bs-cur">גוף טקסט</span><span class="caret">▾</span>`.
2. הוסף `<span class="bs-sub">…</span>` לכל `.bs-opt`.
3. ב-`_syncBlockStyle()` (~7552): לעדכן גם `.bs-cur` בטקסט הסגנון, ולסמן `.cur` בפריט המתאים.
4. CSS בסוף ה-`<style>`.

**בדיקה למרקוס:** מעבר בין H1/P/BLOCKQUOTE מעדכן את טקסט `#blockStyleBtn`; הפריט הפעיל מסומן.

## 5. בורר סוגי רשימה + ניווט-רמות + שמירת רצף

**מצב נוכחי בקוד:**
**כבר מומש בהיקף רחב.** שני `.list-wrap`:
- **תבליטים** (~2582): כפתור ראשי `insertUnorderedList` + `#bulletMenuBtn` (▾) שפותח `#bulletMenu` עם: עיגול מלא (disc), עיגול ריק (circle), ריבוע (square), מקף, משולש, ו**תיבת-סימון (checkbox)** דרך `data-check="1"` → `ul.mw-checklist` עם `::before` של `☐`/`☑` (CSS ~1658–1666).
- **ממוספרת** (~2595): כפתור ראשי `insertOrderedList` + `#numberMenuBtn` (▾) שפותח `#numberMenu` עם: `1.`, עברית `א.`, `a.`, `A.`, `i.`, `I.`, `1)`, `א)`, `01.`, ערבית-הודית. כולל `@counter-style mw-paren-num/heb` (CSS ~1767).
- ניווט רמות: Tab/Shift+Tab מצוין ב-tooltip (CLAUDE.md §11/§13).

**מה לא נוח / מה חסר (דיווח המשתמש):**
1. **מספור רב-רמתי (1, 1.1, 1.1.1)** — המשתמש ביקש זאת מפורשות; **לא קיים** ברשימה (יש סגנונות-counter בודדים אך לא היררכיית "1 → 1.1").
2. **שמירת רצף מספור** בין פריטים מנותקים לא מתועדת/מובטחת.
3. **אישור חזותי** של מעבר-רמה — אין הדגמה שה-Tab עובד; tooltip בלבד.

**מצב רצוי:**
- **להוסיף פריט "מספור רב-רמתי 1 / 1.1 / 1.1.1"** ל-`#numberMenu`. מימוש כמו Word: כל `<ol>` מקבל `class="mw-multilevel"` ושימוש ב-CSS counters מקוננים:
  ```css
  ol.mw-multilevel { counter-reset: mlitem; list-style:none; }
  ol.mw-multilevel > li { counter-increment: mlitem; }
  ol.mw-multilevel > li::before {
    content: counters(mlitem, ".") "  ";
    font-weight:600; }
  ```
  כך רשימה מקוננת (`<ol><li>…<ol><li>`) מציגה אוטומטית 1 → 1.1 → 1.1.1.
- **Tab/Shift+Tab בתוך רשימה** = הזחה/ביטול-הזחה של ה-`<li>` שמייצרת/מבטלת `<ol>` מקונן (מנגנון העימוד הקיים מטפל; לוודא ש-Tab בתוך LI לא מנווט-טבלה — כבר מסויג ב-§11).
- **שמירת רצף**: כשממשיכים רשimah אחרי הפסקה, להשתמש ב-`start` attribute או להמשיך את אותו `<ol>` (התנהגות הדפדפן הטבעית; לתעד שזה היעד).
- **hint חד-פעמי** בבחירת סוג-רשימה: `showHint('Tab = רמה פנימה · Shift+Tab = רמה החוצה')`.

**input → output:**
```
בחר "מספור רב-רמתי" → הרשימה מקבלת ol.mw-multilevel
הקלד פריט → "1. "
Tab → נכנס רמה → "1.1"
Tab שוב → "1.1.1"
Shift+Tab → חוזר ל-"1.2" (רמה אחת החוצה, ממשיך רצף)
checkbox (קיים): לחיצה על ☐ מסמנת ☑ + קו-חוצה (CSS קיים)
```

**מידות/CSS:** להוסיף את בלוק `ol.mw-multilevel` בסוף ה-`<style>`. רוחב `.list-menu` כבר 200px — מספיק.

**איך Word:** Word מציע "Multilevel List" כפתור נפרד עם גלריית סכמות (1/1.1/1.1.1, I/A/1, וכו'); Tab/Shift+Tab מורידים/מעלים רמה ושומרים את הרצף. זה היעד המדויק.

**שלבי מימוש:**
1. CSS בסוף ה-`<style>`: בלוק `ol.mw-multilevel`.
2. HTML ~2598: להוסיף `<div class="li-opt" data-lst="multilevel">1 · 1.1 · 1.1.1 (רב-רמתי)</div>`.
3. JS (מטפל בחירת `data-lst`): כש-`multilevel` → `execCommand('insertOrderedList')` ואז להוסיף `class="mw-multilevel"` ל-`<ol>` שנוצר; אחרת `list-style-type` כרגיל.
4. לוודא ש-Tab בתוך `<li>` (לא בטבלה) מבצע `execCommand('indent')`/`outdent` → יוצר/מבטל `<ol>` מקונן.
5. `showHint` בבחירה.

**בדיקה למרקוס:** בחר רב-רמתי → הקלד 3 פריטים עם Tab בין-שני → התצוגה "1", "1.1", "1.1.1"; Shift+Tab מחזיר רמה.

## 6. Undo/Redo — טווח 250 + חץ נפתח עם מונה ובחירת כמות

**מצב נוכחי בקוד:**
**כבר מומש כשלד.** `.undo-wrap` (~2614): `#btnUndo` (`↶`) + `#btnUndoMenu` (`.undo-caret`, ▾) עם `#undoCount` (`.undo-count` — תג ספירה אדום, CSS ~1670) + `#undoMenu` (`.undo-menu`). `#btnRedo` (`↷`) נפרד. `exec('undo'|'redo')` (CLAUDE.md §12) מגן על free-obj. קיים `window._historyRecord` (נחשף מ-initUndoHistory, §16).

**מה לא נוח / לבדוק (דיווח המשתמש):**
1. צריך לוודא **טווח של 250 צעדים** במחסנית ההיסטוריה.
2. **התפריט הנפתח** צריך להציג כמה צעדים אפשר לחזור, ולאפשר **בחירת כמות** (חזרה של N צעדים בבת-אחת) — לוודא שהשלד מאוכלס.
3. ה-`#undoCount` צריך להתעדכן בזמן אמת.

**מצב רצוי:**
- מחסנית היסטוריה פנימית עם **`MAX_HISTORY = 250`** (אם `initUndoHistory` לא מגביל לכך — להגדיר).
- **`#undoCount`** מציג את מספר הצעדים הזמינים לביטול (נחתך ל-"99+" אם >99 כדי לא לשבור את התג).
- **`#undoMenu`** בפתיחה מאוכלס:
  - כותרת `.undo-head`: "בטל עד 250 צעדים".
  - רשימת אפשרויות מהירות: "בטל צעד אחרון", "בטל 5", "בטל 10", "בטל 25", "בטל הכל".
  - בחירה ב-"בטל N" → לולאה של N קריאות `exec('undo')` (כל אחת עוברת דרך ההגנה על free-obj מ-§12).

**input → output:**
```
הקלד 12 תווים → #undoCount מציג "12"
לחץ ▾ → תפריט: "בטל 5 / בטל 10 / בטל הכל..."
בחר "בטל 10" → 10 ביטולים רצופים, #undoCount→"2"
Ctrl+Z (קיים) → ביטול בודד
מעבר 250 צעדים → הישנים נזרקים (FIFO), המחסנית לא גדלה ללא גבול
```

**מידות/CSS:** קיים מלא (`.undo-menu width:175px`, `.undo-count`, `.undo-opt`). אין שינוי נדרש.

**איך Word:** Undo ב-Word הוא split-button: הכפתור = ביטול בודד; החץ פותח רשימת הפעולות האחרונות ומאפשר לבטל N צעדים בבחירה אחת. ברירת-המחדל של Word ~100; 250 הוא בקשת המשתמש — תקין.

**שלבי מימוש:**
1. ב-`initUndoHistory` (חפש `_historyRecord`): לוודא/להגדיר `MAX_HISTORY=250` וגזירת ה-stack כשעובר.
2. פונקציה `_updateUndoCount()` שמעדכנת `#undoCount` בכל `_historyRecord` ובכל undo/redo.
3. מאזין click ל-`#btnUndoMenu`: לבנות/לפתוח `#undoMenu` עם הפריטים; כל פריט מריץ `for(i=0;i<N;i++) exec('undo')`.
4. אין שינוי בחוקת §12 (ההגנה על free-obj נשמרת בכל קריאה).

**בדיקה למרקוס:** 12 הקלדות → `#undoCount="12"`; "בטל 10" → 10 ביטולים, free-obj לא נמחקים; מעבר 250 לא מנפח זיכרון.
