## 1. בורר הצורות (`openShapePicker`) — אייקונים לא-אחידים + מיקום כפתור-הרחבה

**מיקום קוד:** JS `openShapePicker()` — `MyWord-v2.html:10553-10634`. CSS `.shape-picker` —
3 שכבות-קאסקייד רצופות: `822-831` (בסיס) → `1778-1787` (שדרוג-1) → **`3585-3621`
("סבב-שדרוג 2026-07-04 · 3: בורר-הצורות — תצוגה משודרגת") — זו השכבה שמנצחת
בפועל היום, ולפיה כל המספרים למטה.**

### מה קיים עכשיו (מאומת מהקוד — לפי השכבה המנצחת, 2026-07-04)
- פאנל **`460px`** רוחב, פדינג `12px 14px 16px`, גריד `grid-template-columns: repeat(5, 1fr)` עם `gap: 7px` (הוחלף מ-4 עמודות ל-5 בשדרוג 2026-07-04).
- כל כפתור-צורה: `sp-prev` (תיבת-תצוגה `46px` גובה, רקע-גרדיאנט אינדיגו-עדין, ללא border) + `<svg width=36 height=36>` (`stroke-width:2.2px` בתצוגה-מקדימה בלבד) + `<span>` תווית-טקסט מתחתיו (`font-size: 10px`, `padding: 7px 3px 6px`, `gap: 5px` — **עדיין בלי הגבלת-שורות**). כותרות-קטגוריה (`sp-cat`) הפכו `position: sticky` (2026-07-04) — נחמד לניווט, לא קשור לבעיית-היישור.
- `_buildShapeSVG` (שורה `10332`) מצייר לתוך `viewBox="0 0 100 100"` עם `preserveAspectRatio="none"`. רוב הצורות תופסות `6-92` (כ-86% מהקנבס) — עקבי. אבל `line`/`lineDashed` הן אלכסון-דק בלבד (מ-`5,95` ל-`95,5`), ו"מחברים" (`connLine`/`connElbow` וכו') מציירים path עם strokeWidth=6 בלבד ללא מילוי — משקל-ויזואלי נמוך משמעותית מצורות מלאות כמו `heart`/`star5`.
- **אין הגבלת-גובה לתווית** (`<span>`, גם אחרי שדרוג 2026-07-04): תוויות ארוכות כמו **"ישר-זווית"**/**"מסד נתונים"** (מילה כפולה!) בעמודה-ברוחב-כ-`(460-28-4×7)/5 ≈ 81px` בגופן `10px` **סביר שנשברות לשתי שורות**, בעוד תוויות קצרות כמו **"לב"**/**"קו"** נשארות בשורה אחת. מכיוון ש-CSS Grid קובע גובה-שורה לפי הגבוה-מבין-התאים **בכל שורה בנפרד**, זה יוצר שורות-גריד בגבהים משתנים לאורך הפאנל — זה בדיוק ה-"לא ישרות" שהמשתמש מתאר: העיניים תופסות רשת עם קווים לא-מיושרים בין השורות. **חשוב לדאן/סאמר:** שדרוג 2026-07-04 שיפר הרבה דברים (רשת-5, אייקונים-גדולים-ואחידים 36px, קו עדין 2.2px, כותרות-דביקות) — אבל **לא טיפל בבעיית-גובה-השורה הזו במפורש**, כנראה לא זוהתה אז. זה עדיין פער אמיתי, לא כפילות-עבודה.
- אין tooltip מותאם (רק `title` דפדפן-native, איטי/לא-עקבי).
- כפתור-ה"הרחבה" של **הריבון הראשי** (`#insShapeCaret`, שורה HTML `3763-3768`) **כבר** בנוי כ-`.ribbon-split` עם `.ribbon-caret` — ולפי כלל Glass v2 §3 (`MyWord-v2.html:3018`, `.ribbon-split { flex-direction: row }`) הוא **כבר ממוקם בצד, לא מתחת**. וידאתי בקוד שהחוק הזה מנצח בקאסקייד (מוגדר אחרי ההגדרה הישנה `flex-direction: column` בשורה `1330`, אותה ספציפיות → מנצח האחרון). **אין כאן פעולה נדרשת.**

### מה Word עושה (ground truth)
בגלריית Shapes של Word: אייקונים **חד-גוניים קטנים** (כ-24-28px), **בלי תווית-טקסט מתחת לכל צורה** — שם הצורה מופיע **רק ב-tooltip** בריחוף. הגריד תמיד ישר כי כל תא זהה בגובה (אין טקסט משתנה-אורך שמפריע). קטגוריות מופרדות בכותרות ("Recently Used Shapes" למעלה, "Lines", "Rectangles", "Basic Shapes"...).

### ההצעה הקונקרטית
1. **הסר את תווית-הטקסט מתחת לכל אייקון** (כמו Word) — השאר רק `title` + הוסף tooltip מותאם-CSS (לא native) שמופיע בריחוף. זה פותר את בעיית-הגבהים-המשתנים מהשורש, לא רק מטפל בסימפטום.
   - אם נרצה להשאיר טקסט (נגישות/עברית — ייתכן שרלוונטי כי לא כולם מזהים צורה מ-thumbnail בלבד): קבע `min-height` קבוע לתווית + `-webkit-line-clamp:1` + `text-overflow:ellipsis` כדי שכל תא יהיה **בדיוק אותו גובה** ללא קשר לאורך המילה:
     ```css
     .shape-picker button span {
       height: 13px; line-height: 13px; overflow: hidden;
       white-space: nowrap; text-overflow: ellipsis; width: 100%;
     }
     ```
2. **אחד משקל-ויזואלי בין קטגוריות**: לקטגוריית "קווים"/"מחברים" — הוסף מסגרת-רקע עדינה סביב ה-`sp-prev` (זהה לשאר) כדי שקו-דק לא "ייעלם" ליד צורה מלאה. לדוגמה `stroke-width` מינימלי `6` כבר קיים (טוב) — רק לוודא רקע `sp-prev` אחיד לכולם (`background:#fff;border:1px solid #eef2f7`) — **כבר קיים**, לא לגעת.
3. **כפתור-הרחבה בריבון הראשי:** לא לגעת — כבר תקין (ר' לעיל).
4. **אופציונלי (נחמד-להיות, לא קריטי):** הוסף שורת "לאחרונה השתמשת ב-" בראש הפאנל (כמו Word) שמציגה את `window._lastPick._shape` ועוד 2-3 קודמים (ידרוש `localStorage` מערך חדש `myword2_recent_shapes` — לא קיים היום, `_lastPick` שומר רק את האחרונה, לא היסטוריה).

### spec לדאן — `shape-picker-grid-fix`
**מיקום בקוד (עתידי):** CSS `.shape-picker button span` — **בסוף ה-`<style>`** (אחרי שורה `3621`, סוף בלוק "סבב-שדרוג 2026-07-04 · 3", כדי לגבור עליו בקאסקייד בלי לערוך אותו ישירות)
**טריגר:** פתיחת `openShapePicker` (לחיצה על `#insShapeCaret` או `#insShape` ללא צורה-אחרונה)

**מה קורה:**
1. המשתמש פותח את בורר-הצורות
2. כל 5 העמודות בכל קטגוריה מציגות תאים **בדיוק באותו גובה** (ללא תלות באורך-התווית העברית)
3. גבולות-השורות ישרים אופקית לאורך כל הפאנל

**תוצאה מצופה:** רשת נקייה, ישרה, ללא "מדרגות" בין שורות.
**תנאי שגיאה:** אם תווית נחתכת מוקדם מדי (ellipsis) — לצמצם `font-size` ל-`10px` במקום לקצר עוד את התווית.
**איך Word:** גלריית-צורות ב-Word לא מציגה טקסט כלל מתחת לאייקון — רק ב-tooltip.
**תרחיש בדיקה למרקוס/סאמר:**
```
Input: openShapePicker() → מדוד offsetHeight של כל .sp-grid > button בקטגוריית "גאומטריות"
Expected: כל הערכים זהים (± 1px)
```

### ⚠️ מה כבר תוקן (2026-07-04) — לא לבצע שוב!
`wiki/log.md:428-433` מתעד משוב-משתמש כמעט-זהה מ-2026-07-04: **"הסרגל הצף לא
תואם"**. הטיפול בזמנו (מאומת בקוד, שורות `3499-3542`, גובר על הכל עם `!important`):
```css
#ctxBar { --cb-accent: var(--c-500); }                 /* היה #E8743B כתום קבוע */
#ctxBar button:not(.ctx-arrow):not(.ctx-danger) {       /* אריחי-זכוכית אינדיגו — זהה ל-.ribbon-big .ic */
  background: var(--glass-tile) !important; border: 1px solid var(--glass-bd) !important;
}
#ctxBar button.active,
#ctxBar button.ctx-arrow {                              /* כפתור "עוד" + מצב-פעיל — גרדיאנט אינדיגו */
  background: linear-gradient(180deg, var(--c-500), var(--c-600)) !important;
}
```
כלומר: **המבטא הכללי (accent), רקע-הכרטיס, כפתורי-הפעולה, וכפתור-ה"עוד" העגול —
כולם כבר אינדיגו, לא כתום.** זה סותר ישירות את הניתוח הראשוני (הישן) של הסעיף
הזה שטען ש"ctx-arrow צבוע כתום קבוע" — הטענה ההיא הייתה נכונה **לפני** 2026-07-04
בלבד. **אל תבקשו מסאמר "לתקן" את זה שוב.**

### מה עדיין פתוח בפועל (נבדק שורה-שורה, לא נגוע ע"י 2026-07-04)
תיקון 2026-07-04 נגע **רק** בסלקטורים שמתחילים ב-`#ctxBar` עצמו. שני דברים
נשארו מחוץ להיקף שלו:

**(א) טוקן-הדיו הבסיסי `--cb-ink`** — עדיין `#2a2723` (חום-דיו) ב-root
(שורה `2246`), לא נדרס. זה צובע את `color` של `.tb-body`/כפתורים במצב-מנוחה
(לא hover/active — אלה כן אינדיגו). הריבון הראשי משתמש ב-`--icon-ink: #3A4256`
(כחלחל-אפור). ההבדל עדין (חום מול כחלחל) אך קיים — שאריות-קטנות של "לא אותו
עיצוב בדיוק".

**(ב) שני פופ-אפים צדדיים של `#ctxBar` נשארו כתום-מלא**, כי הם **לא** כלולים
בסלקטור `#ctxBar ...` (הם `document.body` children נפרדים):
```css
/* שורה 2670-2673 — פופ-אפ "סגנון פסקה" (#ctxStylePop) שנפתח מ-ctxBar */
#ctxStylePop button.ctx-style-opt:hover,
#ctxStylePop button.ctx-style-opt.cur {
  background: rgba(232,116,59,.16); color: #E8743B;    /* ← כתום, לא נדרס */
}

/* שורה 2411-2414 — פופ-אפ "גודל גופן" (#ctxSizePop) שנפתח מ-ctxBar */
#ctxSizePop button.ctx-size-opt:hover,
#ctxSizePop button.ctx-size-opt.cur {
  background: rgba(232,116,59,0.16) !important; color: #E8743B !important;  /* ← כתום, לא נדרס */
}
```
אלו **הבאגים-השרידים האמיתיים**: המשתמש פותח את `#ctxBar` (אינדיגו, תואם-בית) ואז
לוחץ על "סגנון פסקה" או "גודל גופן" — ופתאום רואה הדגשת-כתום (hover/נבחר) בתוך
הפופ-אפ שנפתח ממנו. **זה כנראה בדיוק מה שהמשתמש עדיין תופס כ"לא תואם", כי

בנוסף:
- אין `title` על ה-swatches (המשתמש לא יודע מה שם הצבע/hex בלי לנחש).
- אין סימון "זהו הצבע הנוכחי" (ring/checkmark) על אף swatch.
- אין שורת "צבעים אחרונים" בפלטה הבסיסית — למרות שהיא **קיימת** ומיושמת (

  בתוך `openColorWheel`**, שנפתח **רק** דרך חץ-caret ברוחב **15px בלבד**

  (גלגל HSV + hex + recents) קיים בקוד, אבל **מוסתר מאחורי פינת-לחיצה כמעט
  בלתי-נראית** — רוב המשתמשים לא ימצאו אותו ויתקעו עם ה-20-צבעים הבסיסיים.
- ה-"custom color" בפלטה הבסיסית הוא `<input type="color">` — הבורר ה-native
  של מערכת-ההפעלה (נראה שונה ב-Windows/Mac/כל דפדפן, לא "מקצועי"/אחיד).

### מה Word עושה (ground truth — Font Color / Highlight dropdown)
1. **שורת "Automatic"** בראש (איפוס לצבע ברירת-מחדל).
2. **"Theme Colors"** — 10 עמודות (צבעי-ה-theme הפעיל) **× 5 שורות של גוונים-בהירים/כהים** מתחת לכל אחד (tint/shade), סה"כ גריד 10×6 מסודר-מושלם, בלי שבירת-שורה.
3. **"Standard Colors"** — שורה נפרדת של 10 צבעים קבועים (אדום-כהה, אדום, כתום, צהוב, ירוק-בהיר, ירוק, כחול-בהיר, כחול, כחול-כהה, סגול).

6. **Tooltip** בריחוף מציג שם-סמנטי + hex ("Blue, Accent 1, Lighter 40% — #8FAADC").

### ההצעה הקונקרטית
1. **תקן את שבירת-הגריד מיידית** — או שנה `grid-template-columns: repeat(4, ...)` (יתאים למבנה-הנתונים-בפועל של 5 שורות×4), או הרחב את `PRESET_COLORS` ל-24 (6×4) כדי שיתחלק נקי ב-8 עמודות (3 שורות שלמות). **הפתרון הפשוט ביותר: `repeat(4, 26px)` + הגדל swatch ל-26px** — פותר את בעיית-היישור מיידית בלי לגעת בנתונים.
2. **הסר את הכפילות** `#4F6BED` בשורה 3 — להחליף פריט אחד ל-גוון-כחול נוסף (למשל `#0ea5e9` תכלת) כדי שלא יהיו 2 swatches זהים.
3. **הוסף `title` לכל swatch**: `b.title = colorName(c) + ' — ' + c` (אפשר מיפוי-שמות פשוט לפי hue, או פשוט את ה-hex אם אין שם).
4. **הצג "צבעים אחרונים" גם בפלטה הבסיסית** (`.color-palette`) — לא רק ב-`openColorWheel`. הקוד הזה **כבר קיים** (`getRecents()`/`addRecent()` ב-`openColorWheel`, שורות `16993-17009`) — רק לחשוף אותו כ-helper גלובלי (`window._colorRecents`) ולקרוא לו גם מ-`buildColorPalette()`, מוסיף שורה בראש הפלטה.
5. **הרחב את יעד-הלחיצה של ה-caret** מ-`15px` ל-`18-20px` לפחות (יעד-מגע a11y), **או** — עדיף — הוסף שורת-טקסט "🎨 עוד צבעים…" **בתוך** `.color-palette` עצמה (למטה, ליד ה-custom input) שקוראת ל-`openColorWheel` — כך שהמשתמש לא צריך לגלות פינת-לחיצה נסתרת; מקביל בדיוק ל-"More Colors…" של Word.
6. **סמן את הצבע הנוכחי** — בכל render של `.color-palette`, בדוק את `--cur-color` הנוכחי על `#colorBtn`/`#bgColorBtn` והוסף `outline: 2px solid var(--primary)` לswatch התואם.
7. **אופציונלי — טפטפת (eyedropper):** אם `window.EyeDropper` קיים (Chrome/Edge desktop), הוסף כפתור קטן 🎨🖊️ ליד ה-hex input ב-`openColorWheel` שקורא `new EyeDropper().open()` ומזין את התוצאה ל-`hexInput`. Feature-detect — להסתיר לגמרי בדפדפנים ללא תמיכה (Firefox/Safari), לא לשבור שם.

## 4. טאבים ראשיים (הבית/הוספה/פריסה/כלים/תצוגה/קובץ) — 🟡 בינוני, דורש אימות-חי

**מיקום קוד:** CSS בסיס `.tabs .tab` — `80-109`. דריסה ישנה — `2427-2429`. Glass v2 — `3032-3051`
(המנצחת בקאסקייד, ר' ניתוח למטה).

### מה קיים עכשיו (מאומת מהקוד — נדרש אימות-חי לפני שינוי!)
מצאתי **3 הגדרות מתחרות** ל-`.tabs .tab.active`, לפי סדר-מקור בקובץ:
```css
/* שורה 103-109 (בסיס) */
.tabs .tab.active { background: var(--tab-color, var(--primary)); color:#fff; font-weight:700; }

/* שורה 2427 (דריסה "לשוניות כחולות אחידות") */
.tabs .tab.active { background: #4F6BED !important; color:#fff !important; }

/* שורה 3046-3051 (Glass v2 — האחרונה בקובץ, מנצחת בספציפיות-שווה) */
.tabs .tab.active {
  background: linear-gradient(180deg, var(--c-500), var(--c-600)) !important;
  color: #fff !important;
  box-shadow: 0 6px 16px -6px rgba(59,83,216,.55), inset 0 1px 0 rgba(255,255,255,.28);
}
```
לפי חוקי-קאסקייד CSS (ספציפיות זהה, שתי ההגדרות עם `!important`, **מקור מאוחר
מנצח**) — שורה `3046` אמורה לנצח, כלומר **הטאב הפעיל אמור כבר להיות כחול-גרדיאנט
בהיר עם צל**, בדיוק כמו שהתיעוד ב-CLAUDE.md §16 "Glass Design v2" מתאר.

**אם זה נכון בפועל** — התלונה "טאבים אפורים" **לא** מתייחסת לטאב הפעיל, אלא
ל-**5 הטאבים הלא-פעילים**, שכולם חולקים בדיוק אותו עיצוב שטוח:
```css
.tabs .tab {                                  /* שורה 3033-3039 */
  background: rgba(255,255,255,.35);
  border: 1px solid rgba(255,255,255,.5);
  color: #3A4256;                             /* גוון-דיו אחיד לכולם */

```
אין שום זהות-ויזואלית-נפרדת בין "בית"/"הוספה"/"פריסה"/"כלים"/"תצוגה"/"קובץ" כשהם
לא-פעילים — כולם אותו לבן-שקוף + אותו טקסט-אפור-כחלחל. זה **תואם בדיוק** להתנהגות
של Word עצמו (שגם בו טאבים לא-פעילים שטוחים/אפורים, רק הפעיל מודגש) — כך שמבחינת
"Word-parity" זה **לא באג**. אבל זו בהחלט הסיבה שהמראה "משעמם" — 5/6 מהטאבים
נראים זהים, אין "שבירת" מונוטוניות.

> ⚠️ **הערה קריטית לסאמר:** לפני כל שינוי כאן — **לאמת חי בדפדפן** (browser-debug)
> שהטאב הפעיל אכן מציג רקע-כחול-גרדיאנט כמצופה מניתוח-הקוד. אם בפועל נראה אחרת
> (למשל שקוף/אפור), יש כנראה ריצת-JS שמוסיפה `style=""` inline או class נוסף
> שלא אותר בסריקה הסטטית — יש לדווח לדאן כתקלה-runtime נפרדת, לא רק CSS.

### מה Word עושה (ground truth)
Word הקלאסי: טאבים לא-פעילים שטוחים/גוני-אפור-לבן, טאב-פעיל מודגש בכחול/הדגשת-נושא

### שתי אופציות להצעה (לבחירת המשתמש/סאמר)

**אופציה A — Word-parity קפדני (המלצה שמרנית):** לא לשנות את הצבע כלל; רק
להגביר קונטרסט/הבחנה בין טאבים דרך border עדין יותר בין טאבים לא-פעילים +

לשבור את השפה של Word.

**אופציה B — "שבירת המונוטוניות" כמבוקש (חורגת מ-Word, ליברלית):** נצל את
מערכת-הצבעים **הקיימת-כבר** בקוד (`--tab-write #E07A45`, `--tab-textbox #2FA37A`,

לטאבי-הקשר דינמיים כמו `.ctx-format-tab`) והרחב אותה ל-6 הטאבים-הראשיים: פס-צבע

**המלצת נוי:** להתחיל ב-**אופציה A** (בטוחה, לא-הרסנית) ולהציג למשתמש לפני

## 5. ריבוני-הקשר `shapeformat`/`imgformat` — קבוצות ענקיות בלי דפוס Ribbon-Split

**מיקום קוד:** IIFE `initCtxFormatTabs` — `MyWord-v2.html:20101-20435`. פונקציות-בונות:
`bigBtn` (`20132-20138`), `group` (`20139-20148`), `mkRibbon` (`20149-20156`). ריבון
`shapeformat` נבנה ב-`20313-20394`, ריבון `imgformat` ב-`20229-20277`.

### מה קיים עכשיו (מאומת מהקוד)
כל כפתור בשני הריבונים האלה — **בלי יוצא מן הכלל** — נבנה ע"י `bigBtn()`, שמייצר
`button.ribbon-big` מלא (אייקון-אריח 36px בתוך תא 60px גובה / 54px רוחב-מינימלי,
לפי כללי Glass v2, `MyWord-v2.html:2994-3008`) — **גם לפעולות-משנה נדירות-שימוש**
כמו כיווני-יישור בודדים או וריאציית-מיזוג אחת. הפונקציה `group()` בונה **שורת-כפתורים
יחידה בלבד** (`<div class="row">` אחד, ללא `flex-wrap`, ר' CSS `.ribbon .group-titled
.row { display:flex; gap:6px; justify-content:center }` שורה `753`) — כך שקבוצה עם
הרבה כפתורים פשוט מתרחבת לרוחב בלי הגבלה.

תוצאה מדודה-מהקוד (ספירת `bigBtn` בכל `group()` של `shapeformat`):
| קבוצה | # כפתורים | הערה |
|---|---|---|
| סגנון צורה | 7 | מילוי/קו/עובי/העתק-סגנון/הדבק-סגנון/החלף-צורה |
| אפקטים | 6 | צל/גרדיאנט/היפוך×2/רדיוס-פינה/מיקום-מדויק |
| יישור בעמוד | 6 | 6 כיוונים, כל אחד כפתור-ענק נפרד |
| מיזוג צורות | 4 | אחד/חיתוך/חפיפה/הפוך (XOR) |
| סידור | עד 7 | 4×`layerBtns` + שכפל + מחק |
| סיבוב מהיר | 3 | ↺/↻/⊙ |
| שקיפות ונעילה | 2 | מחוון + נעילה |

**8 קבוצות, ~35 כפתורי-ענק בסה"כ** — שורה אחת רחבה-מאוד לכל קבוצה, קבוצות בגדלים
שונים-מאוד זו-לצד-זו (7 מול 2), בלי שום קיבוץ פנימי לזוגות/משולשות כמו שה"בית"
עושה (`toolbar .group-titled .rows` עם **2 שורות** של כפתורים קטנים, ר' CSS
`148-171`). זה בדיוק ה-"לא ישרות" שהמשתמש מתאר: קבוצות שכנות בריבון אחד עם רוחב
דרמטית-שונה, כפתורים ענקיים גם לפעולות שוליות (כמו "אפס סיבוב" או כיוון-יישור
בודד) שבמקום אחר בקוד (הלשונית "הוספה") היו הופכים ל**אופציה מאחורי caret קטן**.

### דוגמת-הניגוד מהקוד עצמו — דפוס `ribbon-split` **כבר קיים ומיושם** בלשונית "הוספה"
`MyWord-v2.html:3740-3786` (לשונית `insert`, קבוצות "לוח"/"טבלאות"/"איורים") —
כל פיצ'ר עם תת-אפשרויות (הדבקה/טבלה/צורות/תיבת-טקסט/תמונה) בנוי כ-`div.ribbon-split`:
**כפתור-ענק אחד מייצג** (`.ribbon-big`, פעולה-ראשית בלחיצה רגילה) **+ caret צר
16px בצד** (`.ribbon-caret`, ▾, פותח פאנל/תפריט עם כל שאר-האפשרויות). זה בדיוק מה
שהמשתמש מבקש ("תמקם את כפתור ההרחבה לידם בצד") — **הדפוס כבר קיים בקובץ**, רק לא
הוחל על `shapeformat`/`imgformat`, כנראה כי אלה נבנו דינמית ב-JS (`initCtxFormatTabs`,
2026-07-08) דרך helper-נפרד (`bigBtn`/`group`) שלא הכיר את `ribbon-split`/`ribbon-caret`.

### מה Word עושה (ground truth)
בלשונית ההקשרית "Shape Format" של Word: קבוצת "Insert Shapes" קומפקטית (גלריה
קטנה + חץ-הרחבה), קבוצת "Shape Styles" — כפתור-גלריה גדול אחד + 3 כפתורי-Fill/
Outline/Effects **קטנים** עם caret (לא כפתורי-ענק לכל וריאציית-צבע/עובי), "Arrange"
— כפתורי Bring-Forward/Send-Backward רגילים (לא ענקיים) + Align עם **caret יחיד**
שפותח תפריט 6 כיוונים (**לא 6 כפתורי-ענק שכנים**), "Rotate" — caret יחיד עם תפריט.
כלומר: Word הופך כל "קבוצת-וריאציות של אותה פעולה" (יישור, סיבוב, מיזוג) לכפתור
מייצג-אחד + caret, בדיוק כמו הדפוס ש-MyWord כבר מיישם בלשונית "הוספה".

### ההצעה הקונקרטית
לא לבנות מנגנון חדש — **לעשות reuse לדפוס `ribbon-split`/`ribbon-caret` הקיים**,
שהוא כבר חלק מ-Glass v2 ומאומת-עובד:
1. **"יישור בעמוד" (6→1+caret):** כפתור-ענק ראשי אחד ("יישור") + caret שפותח
   mw-panel/תפריט עם 6 האופציות (אפשר לעטוף רשימת `bigBtn` קיימת בפאנל `moreBtn`-
   סגנון, כמו שכבר קיים בסרגל-הצף עצמו).
2. **"מיזוג צורות" (4→1+caret):** כפתור-ענק ראשי "מיזוג" (ברירת-מחדל: הפעולה
   האחרונה שנבחרה, כמו `insShape`) + caret ל-3 הווריאציות הנוספות.
3. **"סיבוב מהיר" (3→1+caret):** כפתור-ענק "סיבוב" + caret ל-↺/↻/⊙.
4. **"סגנון צורה" ו"אפקטים":** להשאיר כפתורי-ענק לפעולות-הליבה השכיחות (מילוי,
   צבע-קו, צל, גרדיאנט) אך למזג "העתק-סגנון"+"הדבק-סגנון" לזוג-כפתורים-קטנים

5. **"שקיפות ונעילה":** להעביר את מחוון-השקיפות (`shOpCtrl`) לשורה תחתונה קטנה
   בקבוצה (יש כבר תקדים: `#ctxBar .ctx-cmds.has-rows > .ctx-opacity`, CSS `2828`)
   במקום למדוד אותו כתא-רוחב-מלא בשורת-הכפתורים-הענקיים.
6. **תוצאה כוללת:** מ-~35 כפתורי-ענק ל-~14-16 (חלק כ-`ribbon-split`), קבוצות
   דומות-ברוחב אחת-לשנייה, שורה אחת-או-שתיים לכל היותר במקום קבוצה-ברוחב-500px+.

### מה Word עושה (ground truth — Mini Toolbar)
ה-Mini Toolbar הצף של Word (מופיע בסימון-טקסט/ריחוף) כולל: גופן+גודל, B/I,
צבע-טקסט, מרקר, יישור, **רמת-הזחה (Increase/Decrease list level)**, ו**Styles
gallery מוקטן** (לא תפריט H1/H2 טקסטואלי, אלא preview-קטן של 3-4 סגנונות
נפוצים). Word **לא** כולל Undo/Redo ב-Mini Toolbar (זה תמיד ב-Quick Access Bar
הקבוע למעלה, זמין תמיד) ו**לא** כולל Format Painter ב-Mini Toolbar (הוא כפתור-
ליבה בריבון הרגיל, לא בכלי-הצף). כלומר Word **מכוון** להשאיר את הסרגל-הצף
ל"עיצוב-מהיר של הטקסט הנבחר" בלבד — Undo/Redo ו-Format Painter *לא* אמורים
להיות שם; אבל **סגנון-בלוק (Styles) כן אמור להיות שם**, וזו הפער האמיתי-ביותר
מול MyWord.

### ההצעה הקונקרטית (מכוונת לפי Word — לא "להוסיף הכל")
1. **עדיפות עליונה — סגנון-בלוק בסרגל-הצף:** להוסיף `_sizeChip`-סגנון (כפתור
   `.ctx-style-chip` — **כבר קיים ב-CSS**, `MyWord-v2.html:2644-2649`, מוגדר
   אך לא בשימוש ב-`buildText`!) שפותח את אותו `#ctxStylePop`/תפריט-סגנון שכבר
   קיים בקוד (מוזכר בסעיף 2 הישן, `#ctxStylePop`) — קורא ל-`execCommand
   ('formatBlock', ...)` כמו `blockStyleBtn` של הבית. **תוספת-connect בלבד,
   לא בנייה מאפס** — ה-CSS וה-panel `#ctxStylePop` כבר קיימים ולא מחוברים ל-
   `buildText`.
2. **עדיפות שנייה — בורר-סוג-רשימה:** קישור קטן ל-`#bulletMenu`/`#numberMenu`
   הקיימים דרך caret ליד כפתורי הרשימה ב-`buildText` (לא לבנות תפריט חדש).
3. **הזחה/מרווח-שורות:** להעביר לעמוד-2 של "עוד" (לא לשורה הראשית, לפי חוק
   2-השורות §8) — נוחות בינונית, לא קריטית כמו סגנון-בלוק.
4. **Format Painter / Undo-Redo — לא להוסיף** (Word-parity: אלה שייכים לריבון
   הקבוע, לא לכלי-הצף החולף) — **המלצה מפורשת שלא לממש**, כדי לא "לנפח" את
   הסרגל הצף מעבר למה ש-Word עצמו עושה. אם המשתמש עדיין ירצה - לשאול אותו
   ישירות לפני מימוש (זה סותר את הדפוס של Word).
5. **מחלף-רישיות (`btnCase`):** נמוך-עדיפות, אופציונלי בעמוד-2.
